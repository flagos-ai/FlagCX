## T2 交接配置

交接包记录的配置如下，运行 MPI 时需显式传递给所有 rank：

```bash
export FLAGCX_DMABUF_ENABLE=1
export FLAGCX_SIGNAL_HOST_ENABLE=1
export FLAGCX_MUSA_FORCE_CTA_SYNC=1
export FLAGCX_VMM_ENABLE=0
export FLAGCX_USE_HETERO_COMM=1
export MCCL_TOPO_ENHANCE=0
export MCCL_IB_DISABLE=1
export FLAGCX_IB_DISABLE=0
```

`MCCL_IB_DISABLE` 只控制 MCCL，不能替代 FlagCX 的 IB 开关。T2 单边通信仍需 FlagCX IB/RDMA。HCA、GID、Socket 网卡按实际服务器配置。

DMA-BUF 路线通过已有公共 Net 能力检查接入，不依赖把 MUSA 伪装为 CUDA GDR 平台。设备属性、具体分配的 FD 导出和网卡 MR 注册仍需真实成功，接口非空不代表硬件能力已经验证。

开启 DMA-BUF 时，Device/GDR 分配按页取整，最多尝试 16 次获取页对齐的原生分配；失败明确返回。该实现不返回原生分配内部的偏移地址，保留 musaFree 和 IPC 所需的基址语义。

## CTA 同步选项的边界

`FLAGCX_MUSA_FORCE_CTA_SYNC` 默认关闭，启用后属于实验配置。它在 WORLD sync 入口增加同一 rank 的 CTA 到达同步，不修改 resetSignal，也不修改 K11 用例。

要求同一 grid 的所有 CTA 按相同顺序进入、参与 coop 为整个 CTA，并保证所有 CTA 可持续推进。同一计数器不支持并发 Kernel 共用；普通非 cooperative launch 下存在未驻留 CTA 无法进入导致的调度死锁风险。继续 T4 前需单独检查调用方式，不能直接把该开关视为通用 barrier 修复。
