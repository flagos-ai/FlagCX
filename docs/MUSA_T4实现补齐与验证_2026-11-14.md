# MUSA T4 实现补齐与验证

本次以 `own-after-t3-handoff` 的 T2 交接代码为基础，只修改适配实现并增加运行脚本。公共 T2/T3/T4 Host driver、设备测试 Kernel 和 case 判定均未修改。

## 实现修改

- `musa_adaptor.cc`：实现原生指针类型查询，不再依赖 IPC 导出推断 Host/GPU 类型。沿用 MCCL 的 `MUSART_VERSION >= 38300` 属性字段分界，识别设备和 managed 内存；未被运行时追踪的普通 Host 内存按 Host 返回，其他查询错误向上传递。
- 同一文件对 incoming WRITE 和 GET 本地目标均要求 provider 提供完成后的 GPU 可见性边界。复用公共 GET 完成路径的 `iflush/test`，不将 RDMA READ 的 CQE 单独当成 GPU 已可见；不支持所需边界时明确失败。DMA-BUF 分配、Host 注册和 IPC 实现保留。
- 接入 `getLastError`，使公共 IPC 能力探测在导出失败后可按现有逻辑读取并清除预期的运行时错误，避免带入后续构造阶段；未将设备错误改写为成功。
- `device_api_host_helpers.cu`：新增 MUSA checked 构造入口，检查此前错误、构造 Kernel 属性、线程数及即时启动结果，返回明确状态。保留原有 void helper 符号供旧接口使用。
- `default_dev_api_backend.cc`：MUSA 的 Host Counter 在两种 signal 配置下均显式获取设备地址别名，CPU Proxy 仍使用 Host 地址，别名不单独释放。Net context 数量、helper 可用性和分配大小经过检查；构造启动及同步成功后才把 `_netContexts` 发布到设备 Comm 并缓存结果。失败输出指针清空，沿用资源回收路径。

缺少 MUSA helper 时，设备 Comm 创建不再通过 SizeOf 为零的分支假装成功。其他平台继续使用原 helper 接口，未要求统一改写所有平台的 launcher。

## T4 运行方式

服务器在包含本次修改的仓库根目录执行：

```bash
bash test/unittest/device_api/musa_t4_acceptance.sh
```

脚本默认重编主库、IR Kernel 和 T4 Host 程序，再连续执行三轮。每轮为 8 ranks、两个逻辑节点各 4 ranks，1K～16M、factor 2，执行原 `test_device_ir_unified_inter`。

固定启用 FlagCX IB、DMA-BUF 和 Host SHM signal，关闭 VMM；MCCL 单独关闭 IB。HCA、GID 和 Socket 网卡从调用者已设置的 `FLAGCX_IB_HCA`、`FLAGCX_IB_GID_INDEX`、`FLAGCX_SOCKET_IFNAME` 传入，脚本不硬编码某台服务器的网卡配置。

`FLAGCX_MUSA_FORCE_CTA_SYNC=0` 固定关闭 T2 交接包的实验全 grid 自旋同步。T4 先验证原有 per-context/per-index barrier，不能把所有 CTA 同时驻留作为未经检查的正确性前提，也不将 split arrive/wait 强行改成全 grid barrier。

输出目录：`test/unittest/device_api/t4-results-时间戳.随机后缀/`，保存构建日志、运行命令、环境、每轮日志、原始 MPI 退出码和覆盖统计。

每轮要求：MPI 退出 0、每项 S16～S25 分别 120 条 PASS、无 FAIL/SKIP、一次最终 ALL PASS。Get 缺失或跳过会判失败，不能只凭总体日志或总 PASS 数接受。

如已完成本次全部重编，可用 `BUILD=0`；先跑一轮可设 `ROUNDS=1`。完整稳定性验收仍使用默认三轮。

## 验证记录与限制

本地完成：

- 运行脚本 Bash 语法检查。
- 独立临时目录中用模拟 MPI 验证：2×4 拓扑、三轮完整覆盖、实验同步关闭；S19 少一条、出现 SKIP 均返回 1，MPI 返回 98 时脚本同样返回 98。
- 实现文件差异检查，以及公共 Host driver/设备测试 Kernel 未修改的内容校验。

本机没有 MUSA SDK/GPU，未完成设备编译或真实 RDMA GET 验证。上述模拟只验证脚本组织和验收判定，不构成 T4 PASS。T2 交接包记录的通过结果也不自动覆盖本次实现变更；服务器需回归 T3，再运行 T4，最后回归 T2。

仍保留的非本次配置能力包括 VMM/multicast；未将它们伪装为支持，也未修改未实际捕获根因的 K11 测试。T4 的平台端到端完成状态以服务器完整日志为准。
